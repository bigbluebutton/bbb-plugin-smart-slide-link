## Commands

```bash
npm start                  # Dev server on port 4701
npm run build-bundle       # Production webpack build → dist/
npm run lint               # ESLint on src/ and tests/
npm run lint:fix           # ESLint with auto-fix
npx tsc                    # Type-check src/ (emits to dist-tsc/)
npm run test:unit          # Vitest unit tests (tests/unit/)
npm run test:unit:watch    # Vitest in watch mode
npm run test:unit:coverage # Vitest with coverage
npm test                   # Playwright E2E against a real BBB server (see tests/README.md)
```

Node >= 24.15 (`.nvmrc`). Dependencies are pinned exactly (`.npmrc` has `save-exact=true`).

## Target

Branch `v0.1.x` targets **BigBlueButton 4.0** (4.0.2 bundles `bigbluebutton-html-plugin-sdk`
`1.0.0-beta.3`). `package.json` pins that exact SDK; `manifest.json` `requiredSdkVersion` is the
range the server checks (`~1.0.0-beta.3`).

## Architecture

This is a **BigBlueButton HTML Plugin** built with React + TypeScript. It detects
specially-formatted JSON embedded in presentation slide text and surfaces those links as
presentation toolbar buttons.

### Data flow

```
useCurrentPresentation → slide textUri (+ sessionToken) → fetch → raw slide text
raw slide text → extractSmartSlideLinks → SmartSlideLink[]
SmartSlideLink[] → PresentationToolbarButton[] → setPresentationToolbarItems
```

- [src/index.tsx](src/index.tsx) — bootstraps React, reading `uuid` from the script element.
- [src/components/smart-slide-link/component.tsx](src/components/smart-slide-link/component.tsx) — initializes `BbbPluginSdk`, wires the hooks and registers one toolbar button per link.
- [src/components/smart-slide-link/hooks.ts](src/components/smart-slide-link/hooks.ts) — `useCurrentSlideText` (fetches the current slide's text; aborts stale requests; adds the session token, without which BBB 4.0 answers 401) and `useSmartSlideLinks`.
- [src/components/smart-slide-link/service.ts](src/components/smart-slide-link/service.ts) — plain TS: finds the `BBB` marker (every occurrence), parses the links JSON, keeps only `http(s)` urls, opens links with `noopener,noreferrer`.
- [src/commons/hooks.ts](src/commons/hooks.ts) — mandatory `plg_started`/`plg_stopped` usage logs, the `debug` setting → `pluginLogger.level()`, and the react-intl instance from `useLocaleMessages`.
- [public/locales/](public/locales/) — `en`, `pt-BR` and `index.json`; copied to `dist/locales/` by webpack.

Layout rule: one kind of thing per file (types, constants, intl messages, services, hooks,
component); tests live in `tests/`, never in `src/`.

### Tests

- `tests/unit/` — Vitest; the SDK is replaced by `tests/unit/helpers/sdk-mock.ts`.
- `tests/structural/`, `tests/behavioral/` — Playwright; infra in `tests/core/`, selectors in
  `tests/elements.ts`, meeting setup in `tests/helpers.ts`. The presentation fixture is
  generated by `tests/fixtures/generate-presentation.mjs`.

### Build output

Webpack produces a single UMD bundle at `dist/BbbPluginSmartSlideLink.js`, plus `manifest.json`
and `locales/`. In production they are deployed to
`/var/www/bigbluebutton-default/assets/plugins/bbb-plugin-smart-slide-link/` (served at
`/plugins/bbb-plugin-smart-slide-link/`).

### Linting

ESLint uses the Airbnb TypeScript config. CI runs `npm run lint`, `npx tsc` and
`npm run test:unit:coverage` on every PR — all must pass.
